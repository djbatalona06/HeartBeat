# ui-map.md — the UI as it stands, for a rebuild in another session

A handoff map. It exists so the session that rebuilds the UI/UX (in a different or
similar styling language, chosen for speed and looks) does not have to read 8,190
lines of `app/src/styles.css` to learn what is there. **Nothing here changes any
CSS.** Line numbers are for `main` at `cf8d494`; re-derive them after the stylesheet
moves. Sections 2, 3, 4, 7 and 9 were generated by script over the source tree; the
rest is written from `CLAUDE.md`, `docs/` and the code.

## 0 · The shape of it

| Fact | Value |
|---|---|
| Stylesheet | one file, `app/src/styles.css`, 8,190 lines, 105 sections, imported by `main.tsx` and `standalone.tsx` only |
| Other CSS | `gift/src/*.css`, about 1,500 lines, separate build |
| Naming | flat, feature-prefixed classes (`.garden-`, `.raid-`, `.home-`, `.cal-`), no BEM, no modules, ~1,700 `className` sites |
| Language features in use | `color-mix` ×73, `env(safe-area-*)` ×43, `dvh` ×7, `@media` ×31 (18 are reduced-motion), `:has` ×1, `!important` ×4 |
| Not used yet | `@layer`, nesting, `@container`, `@property`, `@scope`, scroll-driven animation, View Transitions |
| Tooling | none for CSS: no PostCSS, no stylelint, no preprocessor |
| Theming | every colour, radius, shadow, duration and font is a custom property written onto `<html>` at runtime by `themes/tokens.ts` (5 packs × light/dark) |
| Minimum browser | iOS 20+ (owner-confirmed), so every feature above is available |

## 1 · What the styling sits on

Seven things paint, and CSS only owns some of them. A rebuild that treats the
screen as "CSS" will fight the others.

1. **The shell**: `.shell` (`z-index: 1`), the fixed tab bar (`z-index: 2`), the film
   grain on `.shell::after`. The grain is there because there is no body-level
   z-index it could sit at (see the comment at styles.css:215).
2. **Backdrops**: `features/home/SceneBackdrop.tsx` paints the couple's own garden
   on Home and the pack's canvas everywhere else, never both. Token `--z-scene`.
3. **DOM UI**: pages, sheets, tiles, meters, chips (`ui/`, `components/`, `features/*`).
4. **Eve's Garden scene**: Phaser 3.90 on canvas, in `features/eve-garden/scene/`,
   lazy-loaded. Its rules live in C# compiled to WebAssembly and run in a Web Worker
   (`engine/game.worker.ts`, protocol in `engine/protocol.ts`). The Raid Gate is
   rendered *instead of* the garden so Phaser and the 3.5 MB runtime do not boot for a
   screen someone backs out of.
5. **3D mascots**: three.js, one shared hidden WebGL context copied onto 2D canvases
   (`mascots/3d/engine.ts`). The SVG drawings are the loading, offline and no-WebGL
   state, so they are not dead code. The chunk is lazy and kept out of the precache.
6. **Overlays**: sheets, popups, toasts, the command menu, the boss-gate prompt.
7. **Standalone artefacts**: `study/index.html` and `gift/birthday.html` inline the
   whole stylesheet (`cssCodeSplit: false`) and are diff-checked in CI.

Engine rules a styling rewrite must not break (from `CLAUDE.md`): nothing else may
tween `pet.y` while the pet walks; every garden effect that reads the game client
must list `companion` in its deps; DOM may sit above the canvas but must not resize
it mid-fight; the Raid Gate opens on every mount by design.

## 5 · Non-negotiables to carry over

- **Contrast**: `themes/veil.test.ts` composites `--scrim` (72%) and `--glass` (82%)
  over every colour the garden can paint and proves AA. `themes/mood.test.ts` walks
  5 packs × 2 palettes × 3 moods for the accent. A rebuild keeps those tokens or
  rewrites those tests first.
- **One scroll**: Birb and the other pages are budgeted to about one screen
  (`docs/ONE-SCROLL.md`).
- **Touch**: `--tap` is 48px; safe-area insets appear 43 times and the tab bar clears
  them.
- **Motion**: 18 reduced-motion blocks plus `data-calm`; under calm the 3D pose is
  independent of time and the loop draws once.
- **Accessibility**: `forced-colors` and `prefers-contrast` blocks exist; axe runs on
  every route in `npm run visual`.
- **Budgets**: precache ceiling 1260 KiB (`tools/lighthouse.mjs`); the Lighthouse
  check fails a build that preloads the three.js chunk.
- **Artefacts**: rebuild `study/index.html` last, after the final source edit.

## 6 · Target stack, by layer

Confirmed with the owner: iOS 20+, the worry is Eve's Garden, spacing, layering and
engine mechanics, and the goal is modern and proven.

| Layer | Recommendation | Reason |
|---|---|---|
| DOM UI and effects | Native CSS: `@layer`, nesting, container queries, `@property`, scroll-driven animation, View Transitions; Lightning CSS for minify | Runtime tokens keep working; no build change in the three Vite configs; no runtime cost |
| Game drawing | Keep canvas/WebGL (Phaser 3.90); benchmark PixiJS only if the scene outgrows it | CSS should not draw the game |
| Game rules | Keep C# → WebAssembly in a worker | Already off the main thread and tested |
| 3D | Keep three.js behind its one shared context | |
| Layering | One z-scale of tokens (`--z-scene`, `--z-sheet`, `--z-overlay`, `--z-toast` exist), `isolation: isolate` on the scene root, DOM above canvas only | 21 of 31 z-index declarations are raw numbers |
| Spacing | Keep `--space-*`; add stylelint to forbid raw `px` | Pages still mix `Screen` and hand-written `.page` |
| Rejected | Tailwind, CSS-in-JS | Runtime themes; see `docs/TAILWIND.md`, `docs/PULSE.md` |

Runner-up if scoping matters more than anything: CSS Modules over the same tokens
(about 1,700 `className` sites to touch, and the standalone builds need checking).
Whether CSS is the bottleneck is **unmeasured**: profile the `backdrop-filter` uses
and the film grain on a real phone before promising a speed-up.

## 8 · Migration order and acceptance

1. **Tokens first**: add the missing z-scale and an `@layer` order
   (`reset, tokens, base, ui, features, overrides`), wrap the current sheet as a
   `legacy` layer, and prove nothing moved.
2. **Split by section**: move the sections in section 3 into partials under
   `src/styles/`, one entry that imports them in layer order. Keep one import site so
   `cssCodeSplit: false` and the standalone builds behave as now.
3. **`ui/` primitives**, then pages by traffic: Home, Tasks, Mood, Shop/Birb/Raid,
   then the engine-adjacent sections last (Eve's Garden, Raid Gate, heart vial,
   habitat) with the game running.
4. **Guardrails before step 3**: stylelint (no raw px/hex where a token exists,
   class-name pattern), a test that every `var(--x)` is defined (14 are not today,
   section 4), real visual baselines from a CI `visual-frames` artifact.
5. **Done means**: `npm run typecheck`, `npm test`, `npm run visual` (two themes, axe,
   no console errors), the Lighthouse gate, and `npm run study:build` last.
